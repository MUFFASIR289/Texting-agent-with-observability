## 1. Scope

Two surfaces, one design system, built in that order:

| Surface | What it is | When |
|---|---|---|
| **Landing page** | Public marketing page for the product. Cinematic, expressive, one screen of impact then a scroll narrative. | Now — U0…U3, independent of backend milestones |
| **Operator console** | The working UI: approval queue, campaign review, message variants, metrics. | Later — U4+, after backend M9 |

The landing page is built first **and** is the vehicle for extracting the token set,
so the console is a re-use rather than a restyle.

**Not in scope:** customer-facing pages, email templates (those are generated by the
agent, not designed here), and any admin/settings UI.

## 2. The Reference, Deconstructed

The reference is a product page for a Japanese supplement brand. What we take is the
*technique*; what we do not take is anything identifying that company.

### What makes it work

| # | Device | Why it lands |
|---|---|---|
| R1 | **The product sits inside the parentheses of the headline** | `Awaken Energy,` / `( )` / `Drive Everything` — the object is a glyph in the sentence, not an image beside it. One idea carries the whole hero. |
| R2 | **Monochrome by luminance, not hue** | One colour, with the full range from near-black vignette to white bloom. No second hue anywhere except the pill button — which is exactly why that button shouts. |
| R3 | **~14:1 type-scale contrast** | ~140px display against ~10px annotations. Enormous scale range is the entire typographic system; there is no mid-range noise. |
| R4 | **Light is a layer** | Radial glow + vignette + bloom behind the object + cast shadow on the "floor". A flat page reads as a lit room. |
| R5 | **Asymmetric micro-labels break the symmetry** | Tiny side labels are tension, not information. Without them the centred composition reads as a default rather than a decision. |
| R6 | **Held breath before the fold** | One idea per screen, enormous negative space, a single small scroll cue. Nothing competes. |

### What we explicitly do not take

Their wordmark, name, product photography, copy, or the specific green as an
identity. Reproducing a real company's branding is not something I will build or
publish, and it would make the page read as a recolour of theirs rather than ours.
The palette is defined below as a **single hue variable** so the identity decision is
one number, changeable in a second.

## 3. The Two-Mode Problem — the central constraint

This is the part that decides the architecture.

The reference aesthetic is **expressive**: 300-weight type, low-contrast atmosphere,
huge negative space, motion. The operator console is **dense**: tables of send logs,
message variants side by side, metric grids, forms with validation errors. Every
property that makes the hero beautiful actively harms a data table.

| Property | Cinematic mode | Console mode |
|---|---|---|
| Display weight | 300, tracked tight | 500/600, normal tracking |
| Body size | 18–20px | 14px |
| Contrast | Atmospheric, 3:1 on large type | **7:1 minimum on everything** |
| Background | Radial gradient, vignette, bloom | Flat elevated surfaces |
| Density | One idea per screen | Maximum legible density |
| Motion | Parallax, float, reveal | Instant; state changes only |

**Decision.** One token set, two modes. The tokens (hue, luminance ramp, spacing,
radii, font family) are shared. The *application rules* — type scale, contrast floor,
motion budget, density — are per mode. `data-mode="cinematic"` on the landing page,
`data-mode="console"` on the app.

Getting this wrong in the obvious way — styling the console like the hero — produces
a beautiful demo that nobody can actually run a campaign in. The console inherits the
brand's colour and typeface, not its atmosphere.

## 4. Design Tokens

Defined once, consumed by both modes. HSL with a single `--hue` so the brand colour
is a one-line change.

```css
:root {
  /* identity — change --hue to rebrand the entire system */
  --hue: 152;                 /* green, matching the reference family */
  --sat: 45%;

  /* luminance ramp — this IS the palette */
  --l-void:    hsl(var(--hue) 30% 4%);     /* vignette corners        */
  --l-deep:    hsl(var(--hue) 38% 9%);     /* page ground             */
  --l-base:    hsl(var(--hue) 42% 16%);    /* mid field               */
  --l-mid:     hsl(var(--hue) 44% 28%);    /* lit field               */
  --l-lift:    hsl(var(--hue) 40% 44%);    /* near the light source   */
  --l-glow:    hsl(var(--hue) 55% 72%);    /* bloom                   */
  --l-white:   hsl(var(--hue) 20% 98%);    /* type, highlights        */

  /* console surfaces — flat, no atmosphere */
  --surface-0: hsl(var(--hue) 20% 8%);
  --surface-1: hsl(var(--hue) 16% 12%);
  --surface-2: hsl(var(--hue) 14% 17%);
  --border:    hsl(var(--hue) 14% 24%);

  /* semantic — the ONLY places another hue is allowed */
  --ok:    hsl(152 60% 55%);
  --warn:  hsl(38  85% 60%);
  --error: hsl(2   75% 62%);

  /* type */
  --font: "Inter Tight", "Helvetica Neue", Inter, system-ui, sans-serif;
  --font-jp: "Noto Sans JP", var(--font);

  /* space — 4px base */
  --s-1: .25rem; --s-2: .5rem;  --s-3: .75rem; --s-4: 1rem;
  --s-6: 1.5rem; --s-8: 2rem;   --s-12: 3rem;  --s-16: 4rem;
  --s-24: 6rem;  --s-32: 8rem;  --s-48: 12rem;

  --radius: 6px;
  --radius-pill: 999px;
}
```

**Light as a reusable layer** (R4) — one class, used by every cinematic section:

```css
.lit {
  background:
    radial-gradient(120% 80% at 50% 0%,
      var(--l-lift) 0%, var(--l-mid) 28%, var(--l-base) 55%, var(--l-deep) 100%),
    var(--l-deep);
}
.lit::after {                      /* vignette, on top, non-interactive */
  content: ""; position: absolute; inset: 0; pointer-events: none;
  background: radial-gradient(75% 65% at 50% 45%,
    transparent 40%, var(--l-void) 100%);
}
```

## 5. Typography

One family, two weights, extreme scale range (R3).

| Role | Size | Weight | Tracking | Leading | Mode |
|---|---|---|---|---|---|
| `display` | `clamp(3rem, 10.5vw, 9.5rem)` | 300 | −0.025em | 0.94 | cinematic |
| `headline` | `clamp(2rem, 4.5vw, 3.5rem)` | 300 | −0.02em | 1.05 | cinematic |
| `lede` | `clamp(1.05rem, 1.6vw, 1.35rem)` | 400 | 0 | 1.6 | both |
| `body` | 1rem | 400 | 0 | 1.65 | both |
| `ui` | 0.875rem | 500 | 0 | 1.5 | console |
| `data` | 0.8125rem tabular-nums | 500 | 0 | 1.45 | console |
| `label` | 0.625rem | 500 | 0.14em, uppercase | 1.4 | cinematic only |

`label` is the reference's micro-annotation (R5). It is **decorative only** — it may
never be the sole carrier of information, because at 10px it cannot meet contrast
and size guidance. Anything a user must read lives at `ui` or larger.

Self-hosted via `next/font` — no external font CDN, no layout shift, no third-party
request on a page whose whole job is a first impression.

## 6. Motion

| Element | Behaviour | Budget |
|---|---|---|
| Hero entrance | Display lines fade + rise 24px, staggered 90ms | 900ms total |
| Hero object | Idle float, ±8px, 6s ease-in-out, infinite | continuous |
| Object on scroll | `translateY` at 0.25× scroll, subtle scale-down | scroll-linked |
| Section reveals | `IntersectionObserver`, fade + 16px rise, once | 500ms |
| Glow | Slow opacity breathe, ±6%, 8s | continuous |
| Console | State changes only. No parallax, no float. | ≤150ms |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important; animation-iteration-count: 1 !important;
    transition-duration: .01ms !important; scroll-behavior: auto !important;
  }
}
```

Non-negotiable: the page must be fully legible and complete with motion disabled.
Every reveal starts from `opacity: 1` in the no-JS / reduced-motion path — content
that only appears after an animation is content that sometimes does not appear.

## 7. Accessibility — the non-negotiables

This aesthetic fails accessibility by default. These rules are what make it shippable.

| # | Rule |
|---|---|
| A1 | Text carrying information meets **4.5:1** (normal) / **3:1** (≥24px or ≥19px bold). Console mode targets 7:1. |
| A2 | The 10px `label` style is decorative. If it must be read, it is not a `label`. |
| A3 | Every interactive element has a visible focus ring — `outline: 2px solid var(--l-glow); outline-offset: 3px`. Never `outline: none` without a replacement. |
| A4 | Full keyboard path through nav, CTA, and every console control. Skip-to-content link first in DOM. |
| A5 | The hero object is decorative → `alt=""`. The headline is real text, never an image. |
| A6 | `prefers-reduced-motion` honoured everywhere (§6). |
| A7 | Colour never the sole signal: risk levels, campaign states and validation errors carry a label or icon too. Directly relevant here — the console shows CRITICAL/HIGH/MEDIUM/LOW risk. |
| A8 | Semantic landmarks: one `<h1>`, ordered headings, `<nav>`, `<main>`, `<footer>`. |
| A9 | Contrast verified with a token-level check in CI, not by eye. |

## 8. Landing Page — section by section

```
┌─────────────────────────────────────────────────────────────┐
│ NAV        wordmark · links centred · pill CTA right        │  sticky, blur
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ HERO       Stop Churn Before                                │  100vh
│            (  ◆  )        ← object inside the parens  [R1]  │  .lit
│            It Starts                                        │
│            small label L        small label R         [R5]  │
│            lede line · scroll cue                           │
├─────────────────────────────────────────────────────────────┤
│ PROBLEM    Three panels: detection is late / analysis does  │
│            not scale / the loop never closes                │
├─────────────────────────────────────────────────────────────┤
│ LOOP       The twelve-step agentic loop as a luminous       │  the centrepiece
│            diagram; steps light in sequence on scroll       │  after the hero
├─────────────────────────────────────────────────────────────┤
│ GUARDRAILS One table, read-only · no PII in prompts ·       │
│            human approval · policy caps                     │  differentiator
├─────────────────────────────────────────────────────────────┤
│ PROOF      Console screenshots in a dark device frame       │
├─────────────────────────────────────────────────────────────┤
│ CTA        Single action, restated headline treatment       │
├─────────────────────────────────────────────────────────────┤
│ FOOTER     Minimal                                          │
└─────────────────────────────────────────────────────────────┘
```

**Nav.** Wordmark left, links centred, one pill CTA right in `--l-white` with
`--l-deep` text — the single loud element on the page (R2). Sticky with
`backdrop-filter: blur(12px)` and a translucent ground.

**Hero.** The one screen that has to work. Display type in three lines with the
object occupying the middle line's parentheses. Two `label` blocks left and right at
roughly 30% and 70% width. Lede beneath, scroll cue bottom-right.

**Loop section.** This is where a B2B product beats a supplement brand: the twelve
stages of Detect → … → Optimize drawn as a luminous ring or vertical spine, each node
lighting as it enters the viewport. Same light language as the hero, carrying actual
information. It is the page's second peak and the reason someone keeps scrolling.

**Guardrails section.** The security model is the product's strongest claim, so it
gets a section rather than a bullet: one table read-only, no PII in prompts, human
approval bound to content and audience, policy caps that fail loudly. Presented as
four stark statements in `headline` scale, not a feature grid.

## 9. Operator Console — how the system carries over

Built later (U4+), after backend M9. It inherits `--hue`, the luminance ramp, the
typeface and the spacing scale; it inherits none of the atmosphere (§3).

| Screen | Contents | Backed by |
|---|---|---|
| Campaigns list | State, account, segments, created, risk mix | `GET /campaigns` |
| Campaign detail | State timeline, validation results, exclusion counts, token/cost | `GET /campaigns/{id}` |
| Segments | Predicates, sizes, playbook, offer, channel rationale | `/segments`, `/strategy` |
| **Approval** | Variants side by side + rendered preview, approve/reject/revise | `/messages`, `/approve` |
| Metrics | Funnel, per-variant table, A/B verdict incl. `INSUFFICIENT_DATA` | `/metrics` |
| Optimization | Recommendation with the metrics it cites | `/optimization` |
| Query | Natural-language box + grounded answer + tool calls made | `/agent/query` |

Two console rules that come straight from the backend design:

- **The approval screen is the product's centre of gravity.** It must show the exact
  content *and* the audience count that the hash covers — because that is what the
  approver is signing (`FR-42`). A UI that shows only the copy quietly undoes the
  guarantee the backend works hard to provide.
- **`INSUFFICIENT_DATA` must be as visually prominent as a winner.** The backend
  refuses to name a winner below the sample gate (`FR-60`); the UI must not bury that
  verdict in grey small print, or the honesty is lost at the last inch.

## 10. Stack & Structure

**Next.js (App Router) + React + TypeScript**, plain CSS Modules with the tokens in a
global stylesheet.

Chosen because the console is coming: routing, data fetching against the FastAPI
service, and a component library shared across both surfaces. For a single static
page alone this would be more than the job needs — that cost is accepted deliberately
to avoid building the landing page twice.

No CSS framework. This design is gradients, transforms and a type scale; Tailwind or
a component kit would add a layer between us and the exact values the look depends
on, then get overridden everywhere.

```
web/
├── app/
│   ├── layout.tsx            # fonts, tokens, <html data-mode="cinematic">
│   ├── page.tsx              # landing
│   └── (console)/…           # U4+, data-mode="console"
├── components/
│   ├── marketing/            # Nav Hero LoopDiagram Guardrails Proof CTA
│   └── ui/                   # Button Card Table Badge — shared, mode-aware
├── styles/
│   ├── tokens.css            # §4 — single source of truth
│   ├── modes.css             # cinematic vs console rules
│   └── globals.css
├── lib/  hooks/  public/
└── next.config.ts
```

`web/` sits beside `app/` in the repo. Separate deployable, separate lifecycle; the
FastAPI service serves the API and nothing else.

## 11. Performance Budget

The look is cheap if built with CSS and expensive if built with images.

| Metric | Budget |
|---|---|
| LCP | < 2.0s on a mid-tier laptop, 4G |
| CLS | < 0.05 — fonts via `next/font`, every media box reserved |
| JS (initial) | < 135KB gzipped — see the note below |
| Hero object | < 180KB — WebP/AVIF, or SVG/CSS if the object is abstract |
| Fonts | 2 weights, subset, `font-display: swap` |
| Lighthouse | ≥ 95 performance, ≥ 95 accessibility |

Rules: gradients and vignettes in CSS, never as bitmaps. Animate only `transform` and
`opacity`. `will-change` only on the one or two elements that actually need it.
Scroll handlers throttled to `requestAnimationFrame`.

**On the JS figure.** It was 90KB until it was measured. A Next.js App Router page
carrying *nothing at all* — no client components, no CSS modules, plain server markup
— ships **130.7KB gzipped**; the finished landing page ships 130.9KB, so everything
in §8 costs 0.2KB on top of the framework. 90KB was therefore never reachable
alongside the stack §10 chose, and no amount of care in the page could have closed
the gap. §10 accepted the framework deliberately, to avoid building the landing page
twice; this budget is what that decision actually costs, written down. The number to
watch from here is the delta over the floor, not the total.

## 12. Build Milestones

Runs parallel to the backend; U0–U3 depend on no backend milestone.

### U0 — Foundation · ~1 day
Next.js + TS scaffold; `tokens.css` and `modes.css`; `next/font` self-hosting; the
`.lit` background layer; reset and base typography; reduced-motion baseline; a token
page rendering every ramp step and type role.
**Done when:** the token page renders correctly, Lighthouse a11y is 100 on it, and
changing `--hue` visibly rebrands everything.

### U1 — Hero · ~2 days
Nav with sticky blur and pill CTA; the three-line display composition with the object
inside the parentheses; side labels; lede; scroll cue; entrance stagger; idle float;
scroll parallax.
**Done when:** it holds up at 360px, 768px, 1440px and 2560px; readable and complete
with JS disabled; reduced-motion path verified; contrast passes A1.

### U2 — Narrative sections · ~2 days
Problem, Loop diagram with sequential node lighting, Guardrails, Proof, CTA, Footer.
**Done when:** the loop diagram is legible at mobile width and reveals work once,
not on every scroll pass.

### U3 — Polish, a11y, perf · ~1 day
Full keyboard pass; contrast check in CI; metadata and OG image; performance budget
met; cross-browser check including Safari `backdrop-filter`.
**Done when:** every budget in §11 and every rule in §7 is met and verified.

### U4+ — Console · after backend M9
Console mode, app shell, the seven screens in §9, wired to the API.
**Done when:** a campaign can be reviewed and approved end to end in the browser.

## 14. Open Decision

**What goes inside the parentheses?**

The reference puts a physical product there (R1), and that single object carries the
hero. This product is software, so there is no packet to photograph — and this is the
one decision the hero cannot be built without.

| Option | Reads as | Effort |
|---|---|---|
| **Luminous loop ring** — the twelve-stage cycle as a glowing torus, slowly rotating | On-message: the loop *is* the product. Ties the hero to the U2 centrepiece. | CSS/SVG, no asset pipeline |
| **Abstract 3D form** — a glass or liquid-metal shape, floating and lit | Closest to the reference's mood; says "premium", says nothing about churn | Needs a 3D asset or R3F (~+120KB) |
| **A single console card** — one at-risk customer, glowing, floating | Concrete and immediately legible; risks looking like a screenshot in a hero | Pure CSS |
| **Nothing** — type only, light pouring through the empty parens | Most confident and cheapest; loses the object that makes the reference sing | Trivial |

Recommendation: the **luminous loop ring**. It is the only option that is both on-brand
and on-message, it costs no asset pipeline, and it makes the hero and the loop section
one continuous idea rather than two decorated screens.

I have not decided this — U1 needs the answer before the hero is built. U0 does not.
